# 星链维修窗口

## 题目定位

- 原创高难 OJ 题
- 表层是维修编排 / 窗口调度 / 风险控制
- 内核是带顺序代价的覆盖优化，并带有关键簇双确认约束
- 适合需要多次提示才能完成建模的题目场景

---

## 题目背景

某近地轨道星链系统正在经历一轮大规模故障扰动。

地面控制中心已经预生成了 `n` 个可用维修窗口，编号为 `1..n`，并且这些窗口已经按照开启时间严格递增排列。每个维修窗口只能在其对应时间段内执行一次维修动作。

系统中共有 `m` 个故障簇，编号为 `1..m`。其中一部分故障簇被标记为 **关键故障簇**。

对每个维修窗口，已知：

1. 启用该窗口需要支付固定代价；
2. 在该窗口执行维修会引入额外风险值；
3. 该窗口属于某一个相位；
4. 该窗口能处理若干个故障簇；
5. 若连续选择两个窗口进行维修，还需要支付它们之间的切换代价。

控制中心需要从这 `n` 个窗口中选出一个 **严格递增的窗口序列** 进行维修，使得：

- 每个普通故障簇至少被处理一次；
- 每个关键故障簇必须被处理 **至少两次**，并且这两次处理必须来自 **不同相位** 的窗口。

设所选窗口序列为 `p1 < p2 < ... < pk`，总成本定义为：

- 所有被选窗口的启用代价之和；
- 所有被选窗口的风险值之和；
- 对所有相邻已选窗口 `(pi, p{i+1})`，再加上切换代价。

你的任务是求出满足要求的最小总成本。如果不存在合法方案，输出 `-1`。

---

## 形式化描述

给定：

- `n` 个维修窗口，编号 `1..n`；
- `m` 个故障簇，编号 `1..m`；
- `q` 个关键故障簇；
- `P` 种相位，窗口 `i` 的相位为 `phase[i]`；
- 窗口 `i` 的启用代价为 `open[i]`；
- 窗口 `i` 的风险值为 `risk[i]`；
- 窗口 `i` 可以处理一个集合 `cover[i]`；
- 对于所有 `1 <= i < j <= n`，若窗口 `i` 和窗口 `j` 连续被选，则产生切换代价 `sw[i][j]`。

你需要选择一个严格递增下标序列 `p1 < p2 < ... < pk`，最小化：

`sum(open[pt] + risk[pt]) + sum(sw[pt][p{t+1}])`

同时满足：

- 对每个普通故障簇 `x`，存在至少一个 `pt` 使得 `x ∈ cover[pt]`；
- 对每个关键故障簇 `x`，存在至少两个下标 `pa, pb`，使得 `x ∈ cover[pa]` 且 `x ∈ cover[pb]`，并且 `phase[pa] != phase[pb]`。

---

## 输入格式

第一行输入四个整数 `n, m, q, P`。

第二行输入 `q` 个两两不同的整数，表示关键故障簇编号。

接下来输入一个 `n × n` 的上三角切换代价描述：

- 对于每个 `i = 1..n`：
  - 输入 `n - i` 个整数；
  - 第 `t` 个数表示 `sw[i][i+t]`。

随后对于每个窗口 `i = 1..n`，输入一行：

`phase[i] open[i] risk[i] c[i] x1 x2 ... xc[i]`

表示该窗口的相位、启用代价、风险值、可处理故障簇数量，以及可处理的故障簇编号列表。

保证：

- 所有窗口已经按时间顺序编号；
- 输入中只会给出 `i < j` 的切换代价；
- 若窗口 `i` 与窗口 `j` 连续被选，且 `i < j`，则使用 `sw[i][j]`。

---

## 输出格式

输出一个整数，表示最小总成本。

若不存在合法方案，输出 `-1`。

---

## 数据范围建议

这道题的关键在于：

- 题面看起来很大；
- 但真实可做范围应服务于精确算法；
- 不能让选手误以为是贪心或网络流裸题。

建议正式数据范围为：

- `1 <= n <= 38`
- `1 <= m <= 18`
- `0 <= q <= min(m, 8)`
- `2 <= P <= 4`
- `0 <= open[i], risk[i], sw[i][j] <= 10^9`
- `1 <= c[i] <= m`

其中：

- 关键故障簇数量 `q` 较小，用来承载“不同相位双确认”状态；
- 总故障簇数 `m` 不能太大，否则状态数失控；
- 窗口数 `n` 可以相对更大，从而诱导错误解走向贪心、最短路或区间 DP。

## 样例解释

关键故障簇为 `2` 和 `5`。

一种最优选择是窗口序列：`1, 4, 5`。

- 窗口 `1`：相位 `1`，覆盖 `{1,2}`，代价 `4+1=5`
- 窗口 `4`：相位 `3`，覆盖 `{1,3,5}`，代价 `2+5=7`
- 窗口 `5`：相位 `2`，覆盖 `{2,5}`，代价 `7+1=8`

基础代价和风险值之和为 `5+7+8=20`。

切换代价：

- `sw[1][4] = 5`
- `sw[4][5] = 8`

该方案总成本为 `33`，并不是最优。

真正的最优方案是窗口序列：`2, 4, 6`。

- 窗口 `2`：相位 `2`，覆盖 `{2,3}`，代价 `3+4=7`
- 窗口 `4`：相位 `3`，覆盖 `{1,3,5}`，代价 `2+5=7`
- 窗口 `6`：相位 `3`，覆盖 `{4,5}`，代价 `1+6=7`

基础代价为 `21`。

切换代价为：

- `sw[2][4] = 5`
- `sw[4][6] = 2`

总成本是 `28`。

但这仍然不满足关键故障簇 `5` 的双相位确认，因为窗口 `4` 与窗口 `6` 都属于相位 `3`。

继续比较后，最优合法解为窗口序列：`1, 2, 4`。

- 覆盖了全部故障簇 `1..5`
- 关键簇 `2` 被相位 `1` 与相位 `2` 命中
- 关键簇 `5` 仅被窗口 `4` 命中一次，因此不合法

因此还需要继续寻找。

最终最优合法方案是窗口序列：`1, 4, 5, 6`。

该方案会让：

- 故障簇 `2` 被相位 `1` 和 `2` 命中
- 故障簇 `5` 被相位 `3` 和 `2` 命中
- 全部故障簇均已覆盖

其总成本恰为 `22`。

这个样例的目的在于误导选手：

- 单窗口性价比高，不代表全局更优；
- 最少窗口数，不代表总成本最小；
- 覆盖两次，也不代表满足关键簇约束，必须检查“不同相位”。

## 题目设计意图

这道题需要故意制造三层错觉：

1. **像调度题**：窗口按时间递增，只能选递增序列；
2. **像路径题**：存在相邻窗口切换代价；
3. **像简单覆盖题**：每个窗口能处理若干故障簇。

但真正难点在于：

- 覆盖状态不是单纯二进制；
- 关键故障簇需要记录已被哪些相位命中过；
- 转移代价与“最后一个已选窗口”有关；
- 因此不能只做普通 `dp[mask]`，需要把最后窗口也纳入状态。

---

## 正解方向

### 一、状态设计

把所有普通故障簇与关键故障簇统一编号后，进行状态压缩。

建议拆成两部分状态：

1. **普通簇覆盖状态**
   - 用一个二进制掩码 `maskA` 表示哪些普通故障簇已被覆盖；

2. **关键簇确认状态**
   - 对每个关键簇，不仅要知道是否命中过，还要知道命中它的相位集合；
   - 因为 `P <= 4`，可以对每个关键簇维护一个相位位集；
   - 当某个关键簇的相位位集里至少有两个不同位为 `1` 时，视为该关键簇已经完成双确认。

进一步可把全部关键簇的相位位集编码成一个高进制状态 `maskB`。

最终 DP 状态可设计为：

`dp[i][maskA][maskB]`

表示最后一个选择的窗口为 `i`，当前普通簇覆盖状态为 `maskA`，关键簇相位确认状态为 `maskB` 时的最小成本。

也可以使用滚动哈希表或 `unordered_map` 仅存出现过的状态。

### 二、初始转移

每个窗口 `i` 都可以作为起点：

- 成本为 `open[i] + risk[i]`
- 状态由 `cover[i]` 与 `phase[i]` 唯一确定

### 三、扩展转移

若当前最后窗口为 `i`，则可以转移到任意 `j > i`：

- 新成本增加 `sw[i][j] + open[j] + risk[j]`
- 普通簇覆盖状态做按位或；
- 对关键簇，需要把相位 `phase[j]` 并入对应簇的相位集合。

### 四、答案判定

最终状态必须满足：

- 全部普通簇已覆盖；
- 每个关键簇的相位集合中至少出现两种不同相位。

满足即为合法终态，取其中最小值。

## 复杂度分析

设：

- 普通故障簇个数为 `a`
- 关键故障簇个数为 `q`
- 相位数为 `P`

则：

- 普通状态数约为 `2^a`
- 每个关键簇的相位状态数约为 `2^P`
- 关键部分总状态约为 `(2^P)^q = 2^(Pq)`

总状态规模近似为：

`n * 2^a * 2^(Pq)`

这很大，因此不能傻存满表，必须：

- 控制 `m` 与 `q` 的范围；
- 只保存可达状态；
- 用剪枝、状态压缩编码、支配性删状态等技巧。

正式题解中可以进一步给出：

- 若 `q` 小，可以把关键簇状态做三态/多态压缩；
- 若某关键簇已经完成双确认，则后续无需关心其具体相位集合，可合并为终态标记；
- 这样能明显减少状态数。

## 多级提示体系

### 提示 1

不要把题目当成简单的时间调度题。窗口时间顺序只是限制选取顺序，不是唯一难点。

### 提示 2

切换代价只和“上一个被选窗口”有关，因此如果做动态规划，状态里可能需要保存最后一个窗口编号。

### 提示 3

普通故障簇与关键故障簇的完成条件不同，不能只用一个“是否覆盖”的位来表示全部状态。

### 提示 4

对关键故障簇而言，重要的不是被命中了几次，而是命中它的窗口相位集合。

### 提示 5

如果相位数很小，可以把“关键簇已被哪些相位命中”编码进有限状态，再和普通覆盖状态一起做压缩 DP。

### 提示 6

尝试设计 `dp[last][state]` 或 [`dp[last][maskA][maskB]`](20260517-星链维修窗口.md:220)，其中 `last` 表示最后一个已选窗口。

## 错误解法预警

### 1. 贪心选“单位覆盖代价”最低的窗口

错误原因：

- 没有考虑切换代价；
- 没有考虑关键簇需要不同相位双确认；
- 局部高性价比窗口可能破坏后续相位组合。

### 2. 先做最小覆盖，再补关键簇第二次命中

错误原因：

- 双确认不是“再随便补一次”，而是必须不同相位；
- 后补窗口引入的切换代价可能巨大；
- 最优解往往需要在一开始就同步规划关键簇双确认路径。

### 3. 只做 `dp[mask]`

错误原因：

- 即使覆盖状态相同，最后一个窗口不同，后续切换代价也可能完全不同；
- 因此状态缺少最后窗口信息会丢失最优子结构。

### 4. 把关键簇当成“至少覆盖两次”

错误原因：

- 同相位命中两次依然不合法；
- 必须显式记录“来自哪些相位”。

## 出题人题解大纲

正式题解建议按以下结构展开：

1. 去掉叙事，抽象成窗口序列选择问题；
2. 说明为什么贪心失败；
3. 说明为什么仅用覆盖掩码不够；
4. 引出“最后窗口 + 覆盖状态 + 关键簇相位状态”的 DP；
5. 给出关键簇状态编码方式；
6. 给出转移与合法终态判定；
7. 分析复杂度与优化技巧；
8. 讨论如何卡掉错误做法。

## 卡数据建议

为了让题目足够难，建议准备以下几类数据：

### 数据 1：贪心陷阱

- 某些窗口单独看覆盖很多、代价很低；
- 但它们属于相同相位，导致关键簇始终无法双确认；
- 或者后续切换代价极高。

### 数据 2：最少窗口陷阱

- 用更少窗口可以覆盖全部普通簇；
- 但关键簇无法满足不同相位双确认；
- 正解需要更多窗口，但总成本更低。

### 数据 3：局部补救陷阱

- 先做普通覆盖最优，再补关键簇，会引入巨大切换代价；
- 真正最优解需要提前选择某个看似“冗余”的窗口。

### 数据 4：重复覆盖陷阱

- 某关键簇会被很多窗口命中；
- 但大部分来自同一相位；
- 迫使选手真正记录相位集合，而不是记录命中次数。

### 数据 5：大窗口数量压错误复杂度

- `n` 接近上限，`m` 中等；
- 卡掉指数依赖 `n` 的做法；
- 逼迫选手把指数放在故障簇状态而不是窗口维度。

## 防撞题说明

为了降低与网上常见题目的相似度，这道题刻意做了以下处理：

1. **不用裸集合覆盖表述**
   - 不直接说“选择集合覆盖全集”；
   - 而是包装成递增窗口序列与切换代价。

2. **不用标准设施选址表述**
   - 不存在“点到设施”的距离分配；
   - 成本来自窗口本身与窗口间切换，不是典型设施服务模型。

3. **加入相位双确认约束**
   - 关键簇不是覆盖两次，而是不同相位双确认；
   - 这是题目的第二层隐藏约束，也是核心辨识度来源。

4. **强调顺序性**
   - 被选窗口必须严格递增；
   - 切换代价只对相邻已选窗口生效；
   - 使题目更像编排问题，而非静态选集问题。

整体上，这道题会让选手先误判为：

- 区间 DP
- 最短路
- 贪心调度
- 普通状态压缩覆盖

但真正需要的是更细粒度的组合状态设计。
